# Week 2 — Tokens are learned, not given

**Time:** 5h · **Deliverable:** your own BPE, plus a number that explains your bill
**Prereq:** week 1

## The one idea

A model never sees text. It sees integers. Which integers — how the string is
chopped — is a *learned* decision made before training, by counting byte pairs.
That one choice sets your context length, your cost per character, your
multilingual quality, and a whole family of bugs (arithmetic, rare strings,
trailing whitespace) that look like model failures and are not.

## Derive (60 min)

1. Vocabulary size is a budget: 256 symbols is too few (sequences explode),
   1M symbols is too many (each embedding row is params you must train).
   BPE splits the difference greedily.
2. Greedy merging = repeatedly take the most frequent adjacent pair, mint a new
   symbol for it. That is the entire algorithm. It optimises nothing global; it
   is a heuristic and it is fine.
3. Compression is the point: fewer tokens per character means fewer forward
   passes per document means cheaper inference and longer effective context.
4. Consequence: the *same string* can be 1 token or 20 depending on the
   tokenizer. So "context window is 200k tokens" is not a claim about text.

Worked number: `" the"` is one token in GPT-style vocabularies. `"  the"` (two
spaces) is usually two. A prompt with inconsistent spacing silently costs 30-40%
more tokens. Nobody's eval catches that.

## Build (120 min)

`lab.py`:

| Function | Contract |
|---|---|
| `split_words` | pre-split so merges cannot cross word boundaries |
| `pair_counts` | Counter of adjacent pairs across all words |
| `merge_word` | left-to-right, non-overlapping replacement |
| `train_bpe` | greedy merges until `vocab_size` or `min_count` |
| `encode_with_merges` | apply merges in *learned rank* order, not id order |
| `token_report` | chars, tokens, chars/token, bytes/token |

The subtle one is `encode_with_merges`: naive implementations re-merge in
arbitrary order and produce a vocabulary that is not the one that was trained.
Test 5 catches it. Yours should not be caught by it.

## 2026 lens

- **Still true:** BPE is what ships; tokens are the unit of cost, latency, and
  context; tokenizer-bound evals are not comparable across model families.
- **Changed:** byte-latent and tokenizer-free architectures are a real research
  direction again (patch-based and byte-level models), largely *because* BPE's
  pathologies are annoying. Also: multimodal models spend tokens on images, so
  "token" now means "any discrete unit the model attends over".
- **Open:** whether fixed tokenizers survive the decade, or whether learned
  compression becomes part of training.
