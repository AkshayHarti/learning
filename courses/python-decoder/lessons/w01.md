# Week 1 — Prediction is compression

**Time:** 5h · **Deliverable:** an n-gram language model you can quote perplexities for
**Prereq:** none

## The one idea

A language model is a probability distribution over the next token. Nothing more.
If it assigns high probability to what actually came next, it can *encode* text in
fewer bits. So "learning to predict" and "learning to compress" are the same
optimisation, and cross-entropy is literally the average number of bits per token
the model spends. That single identity explains why scaling works, why perplexity
is the ancestral eval, and why data quality beats architecture.

## Derive (60 min)

1. Surprisal of an event with probability `p` is `-log2 p`. Why log? Because
   independent events must add: `-log(p1p2) = -log p1 - log p2`.
2. Entropy `H(p) = -Σ p log2 p` is the *average* surprisal — the floor on bits per
   symbol for any code.
3. Cross-entropy `H(p,q) = -Σ p log2 q` is what you pay when you use model `q` but
   the world is `p`. Always `H(p,q) ≥ H(p)`, with equality iff `q = p`.
4. Perplexity `= 2^H`. Read it as "effective branching factor": ppl 8 means the
   model is as confused as a uniform choice among 8 options.

Worked number: a fair die has `H = log2 6 = 2.585` bits. A model that puts 0.5 on
the true face charges you 1 bit; a model that puts 0.01 charges 6.64 bits. Get
comfortable with that asymmetry — it is why one confidently wrong token can cost
more than twenty easy ones.

## Build (120 min)

`lab.py` — implement, until `pytest weeks/w01_prediction` is green:

| Function | What it must do |
|---|---|
| `entropy(p)` | bits, ignore zeros |
| `cross_entropy_bits(p, q)` | bits, `+inf` if `q` has a zero where `p` doesn't |
| `kl_bits(p, q)` | divergence, ≥ 0 |
| `perplexity_from_nats(loss)` | convert a natural-log loss (what training prints) to ppl |
| `NgramLM` | add-k smoothed n-gram char model: `fit`, `prob`, `logprob`, `perplexity` |

Then check yourself against reality, not against the tests:

```bash
uv run python -m weeks.w01_prediction.report
```

It prints bits/char for uniform, bigram, trigram, and 4-gram on held-out text.
Your numbers should land near `4.7 / 3.3 / 2.6 / 2.4` for the toy corpus. If the
trigram is not clearly better than the bigram, you have a bug, not a discovery.

## Break it (30 min)

Delete the `k` smoothing term (`k=0`). Watch held-out perplexity become `inf` on
one unseen context. Then reason: what does GPT do about unseen contexts that an
n-gram cannot? (Answer: it doesn't have contexts, it has vectors — week 3.)

Second break: set `n=6` and watch *train* perplexity collapse while held-out
perplexity gets worse. You have just reproduced overfitting and the reason every
eval needs a holdout.

## 2026 lens

- **Still true:** cross-entropy is the loss; perplexity is comparable *only* across
  models with the same tokenizer; bits-per-byte is the tokenizer-independent
  version and is what serious pretraining papers report.
- **Changed:** nobody ships on perplexity now, but the *compression* framing came
  back: it is the cleanest explanation of why more data helps a fixed model, and
  why "shrink the model, keep the data" sometimes wins.
- **Open:** whether the next-token objective is sufficient for reasoning, or just
  a convenient surrogate. Week 5 and 6 are where that argument lives.
